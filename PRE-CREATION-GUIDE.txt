PRE-CREATION GUIDE

Before creating this Bitcoin Core descriptor signer, confirm:

[ ] I have verified the Tails ISO.
[ ] I am using Bitcoin Core v32.0rc2 and have independently verified the release/signing fingerprints I trust.
[ ] The project folder is beside bitcoin-32.0rc2-x86_64-linux-gnu.tar.gz.
[ ] I have physically air-gapped this computer where practical.
[ ] I understand this creates a Bitcoin Core wallet containing private signing material.
[ ] I have secure backup media ready.
[ ] I know whether this Core signer should export BIP87 or BIP48 native-P2WSH.
[ ] I have a coordinator/wallet application ready to build the final PUBLIC descriptor.
[ ] I will independently verify the final policy, addresses, thresholds, timelocks, and recovery paths before funding.
[ ] I have disposable funds or a test network available for an end-to-end signing test.

AIR GAP

tails.sh disables NetworkManager networking and requires it to report disabled.

Core also starts with:

-networkactive=0 -listen=0

These are defense in depth, not substitutes for physical isolation.

LOCAL ACCOUNT CHOICE

The generator offers:

BIP87:
    m/87h/coin_typeh/0h

BIP48 native-P2WSH:
    m/48h/coin_typeh/0h/2h

This choice controls only the local Core signer.

For example, a Liana policy may use BIP48 for an immediate-spend key and BIP87 for a recovery key. Choose the role you want this Core signer to occupy.

WHAT WILL HAPPEN

1. Core creates a blank private-key-enabled descriptor wallet.
2. Core generates a fresh root with addhdkey.
3. Core derives the selected account.
4. The public [fingerprint/path]xpub is displayed as text + QR.
5. Add that public key to the wallet/coordinator policy.
6. Export the complete PUBLIC descriptor.
7. Paste that descriptor into the offline signer.
8. Bitcoin Core parses and canonicalizes it.
9. The helper requires this exact local [origin]xpub identity to appear.
10. Core derives the matching account xprv internally.
11. Only exact occurrences of this local identity are replaced with the xprv.
12. Core must canonicalize the private form back to the identical public descriptor and multipath expansion.
13. The descriptor is imported.
14. Core must report the local account key as private/signable and attached to the expected descriptor.

IMPORTANT

The helper deliberately does NOT decide whether the descriptor policy is safe or sensible.

A Core-valid descriptor can still contain:
- the wrong threshold;
- the wrong cosigners;
- the wrong timelock;
- the wrong recovery branch;
- an unintended Taproot/Miniscript policy.

Verify the policy independently before funding it.
